## 기획서

본 문서는 코딩 테스트 플랫폼의 목적, 대상 사용자, 기능/비기능 요구사항, 시스템 범위, 단계별 구현 로드맵을 정리한 기획 명세서이다. 본 프로젝트는 소프트웨어 공학의 정석적 방법(요구사항 정의 → 설계 → 단계적 구현 → 문서화)을 준수하여 진행하는 예제이며, 각 작업(Phase)이 끝날 때마다 본 문서군을 갱신한다.

## 1. 목적

온라인에서 문제를 풀고, 코드를 제출하면 자동 채점이 이루어지며, 대회와 시험을 운영할 수 있는 **server-client 기반 코딩 테스트 플랫폼**을 구현한다. 백엔드는 Spring Boot 기반 REST API 서버로 제공되고, 프런트엔드는 이를 소비하는 클라이언트로 분리한다(프런트 연동은 후속 Phase).

## 2. 목표

- 문제·테스트케이스·제출·채점을 중심으로 한 핵심 도메인 구현
- 대회/시험 운영(개설, 문제 배정, 감독자 배정, 참가/응시, 결과 조회) 지원
- 기관(Organization)·감독자(Supervisor) 역할 분리를 통한 운영 책임 명확화
- 채점 기능을 인터페이스로 추상화하여 Mock → 실제 채점기로 무중단 교체 가능하게 설계
- PostgreSQL 영속화 및 Docker Compose 기반 번들 배포

## 3. 대상 사용자(Actor)

| Actor | 설명 |
|-------|------|
| User | 문제를 풀고 제출하며, 대회 참가·시험 응시·해설 등록을 수행하는 일반 사용자 |
| Supervisor | 대회/시험의 실제 운영·관리 책임을 가지는 감독자 |
| Organization | 문제/대회/시험을 소유하고 개설하는 운영 주체(기관) |
| OAuth Provider | 소셜 로그인을 제공하는 외부 인증 주체(향후 Phase) |
| Code Judge | 제출 코드를 컴파일·실행·비교하는 채점 시스템(현재 Mock, 향후 실제 구현) |

## 4. 기능 요구사항

### 4.1 사용자/계정/인증
- 사용자·감독자 생성 및 조회, 사용자 정보 수정/삭제
- JWT 인증: 개발용 로그인(역할+id→토큰), 읽기 공개 / 변경계 인증 필요
- (향후) 실제 OAuth2 소셜 로그인(Google)

### 4.2 문제
- 문제 CRUD, 카테고리 N:M 연결
- 문제별 테스트케이스 CRUD
- 사용자별 문제 풀이 상태(UserProblem) 관리

### 4.3 제출/채점
- 코드 제출 시 채점 수행 → 제출 기록(코드·언어·상태·점수) 저장
- 채점 결과에 따른 풀이 상태 갱신
- 제출 단건/유저별/문제별 조회

### 4.4 대회
- 대회 CRUD, 대회 문제 배정(순서·배점), 감독자 배정
- 대회 참가 신청(중복 검사), 참가자 목록 조회

### 4.5 시험
- 시험 CRUD, 시험 문제 배정(순서·배점), 감독자 배정
- 시험 응시 신청(중복 검사), 결과 목록 조회

### 4.6 기관
- 기관 CRUD, 기관-문제/대회/시험 소유 관계 등록

## 5. 비기능 요구사항

| 항목 | 내용 |
|------|------|
| 유지보수성 | 도메인별·계층별 책임 분리(SRP), DTO로 API-엔티티 결합도 최소화 |
| 확장성 | 채점기 인터페이스화(OCP/DIP), N:M 연결 테이블로 도메인 확장 흡수 |
| 일관성 | `ApiResponse<T>` 공통 응답, `GlobalExceptionHandler` 전역 예외 처리 |
| 영속성 | 운영 환경 PostgreSQL, 로컬/테스트 H2(프로파일 분리) |
| 배포성 | Docker Compose로 app + DB 일괄 기동 |
| 문서화 | 기획/구조/흐름/다이어그램을 docs로 관리, Phase마다 갱신 |

## 6. 시스템 범위

포함: 위 4장 기능의 REST API 백엔드, 영속화, 컨테이너 번들.
제외(현 시점): 실제 코드 채점 실행, 인증/인가, 실시간/배치 처리, 프런트 연동. → 7장 로드맵에서 단계화.

## 7. 구현 로드맵(Phase)

| Phase | 내용 | 상태 |
|-------|------|------|
| 1 | 인프라 & 영속성: PostgreSQL, 프로파일 분리, Docker Compose, 문서 베이스라인 | 완료 |
| 2 | 실제 채점: `CodeJudgeService`(앱 내 ProcessBuilder 실행 + Testcase 비교, Python/Java) | 완료 |
| 3 | 인증/인가: JWT 인증(개발용 로그인), 읽기공개/쓰기인증 (실제 OAuth2는 후속) | 완료 |
| 4 | 배치/집계: 대회·시험 자동 마감, 랭킹/합격 집계 (@Scheduled + 수동 트리거) | 완료 |
| 5 | 프런트엔드 연동: 정적 FE를 Spring 동일출처 서빙 + REST API 소비(로그인/문제/제출 핵심 루프) | 완료 |
