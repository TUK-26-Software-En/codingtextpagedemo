# 소프트웨어 공학 단계별 명세서

본 디렉터리는 소프트웨어 공학의 표준 개발 단계(요구사항 분석 → 아키텍처 분석 → 설계 → 상세 설계 → 품질 정제 → 최적화)에 따라, **코딩 테스트 플랫폼** 프로젝트의 산출물을 단계별 명세서로 정리한 문서 모음이다. 각 명세서는 실제 구현(Phase 1~5)을 근거로 작성되었으며, 정석적 개발 절차의 산출물 예시로 기능한다.

## 단계 ↔ 산출물 매핑

| 단계 | 주요 활동 | 핵심 목표/관점 | 기본 구조·설계 내용 | 산출물(문서) |
|------|-----------|----------------|----------------------|--------------|
| 요구사항 분석 | 시나리오 및 유스케이스 | 사용자 의도 파악 (What) | 기능·비기능 요구사항 정의 | [01_유스케이스_명세서.md](01_유스케이스_명세서.md) |
| 아키텍처 분석 | 4 View 분석 | 설계 제약사항 파악 (Why) | 논리·프로세스·개발·물리 관점 분석 | [02_4plus1View_다이어그램_문서.md](02_4plus1View_다이어그램_문서.md) |
| 설계 | 아키텍처 스타일 결정 | 기본 SW 구조 확립 | 거시적 구조(Style) 결정 (Layered, C/S) | [03_시스템_아키텍처_구조도_명세서.md](03_시스템_아키텍처_구조도_명세서.md) |
| 상세 설계 (구조) | 클래스 및 관계 설계 | 객체 간 역할 분담 (Structure) | 클래스 관계·인터페이스 정의 | [04_클래스_다이어그램_확정_명세서.md](04_클래스_다이어그램_확정_명세서.md) |
| 상세 설계 (내부) | 자료구조 및 알고리즘 | 자원 효율성 확보 (Efficiency) | 클래스 내부 데이터 저장 방식 결정 | [05_데이터저장_방식_명세서.md](05_데이터저장_방식_명세서.md) |
| 품질 정제 | SOLID 원칙 적용 | 설계 유연성 확보 (Quality) | 유지보수성 향상 구조 교정 | [06_응집도_결합도_관점_명세서.md](06_응집도_결합도_관점_명세서.md) |
| 최적화 솔루션 | 디자인 패턴 적용 | 문제 해결 노하우 (HOW) | 검증된 패턴으로 상세 설계 구체화 | [07_디자인패턴_적용내용_명세서.md](07_디자인패턴_적용내용_명세서.md) |

## 문서 간 의존(작성 순서)

```
01 요구사항 → 02 아키텍처(4+1) → 03 아키텍처 스타일 → 04 클래스 → 05 데이터저장
                                                          ├→ 06 응집도/결합도(SOLID)
                                                          └→ 07 디자인 패턴
```
